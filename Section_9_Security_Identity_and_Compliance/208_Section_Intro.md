# 208. Section Intro

**Security, identity and compliance** for generative AI: protect the applications and their data, and manage access across the whole architecture.

## What the section covers

| Topic | Purpose |
|---|---|
| **Principle of least privilege**, data **masking** and **salting** | Foundation of secure design; limit exposure of sensitive data |
| **IAM** | Fine-grained access to models, datasets, vector stores, prompts, secrets and APIs |
| **Encryption at rest and in transit**, **KMS** | Protect data across the AI pipeline |
| **Amazon Macie** | Detect **PII** and other sensitive data |
| **Secrets Manager** | Store API keys, connection strings and credentials |
| **Amazon Cognito** | User authentication and authorisation |
| Protection against **malicious inputs** | Defend AI endpoints |
| **VPC** and **PrivateLink** | Isolate components and keep traffic to Bedrock, databases and other services off the public internet |
