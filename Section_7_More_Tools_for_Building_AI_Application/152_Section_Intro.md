# 152. Section Intro

This section covers the AWS services and patterns that turn a **foundation model** into a production application: connecting the AI logic to the rest of the system, automating workflows, and building integration points that scale.

## What is coming

| Topic | Purpose |
|---|---|
| **AWS Lambda** | Integration patterns, including calling **Bedrock** from serverless functions |
| **Amazon API Gateway** | Expose generative AI features securely through your own APIs |
| **AWS AppConfig** | Change settings on the fly, such as **which model** is used |
| **AWS Step Functions** | State machines, stopping conditions, **circuit breakers**, **ReAct** and chain-of-thought routing; a lab chains prompts with Bedrock |
| **CodeBuild, CodeDeploy, CodePipeline** | **CI/CD** for generative AI applications |
| **MLflow** | Track experiments and performance across model configurations |
| **AppSync** | GraphQL APIs |
| **Outposts, Wavelength** | Hybrid and edge deployments |
| **SQS** | Asynchronous workloads |
| **Amplify** | Fast front-end integration |
| **EventBridge, SNS, AppFlow** | Event-driven patterns |

It closes with best practices for **foundation model API interfaces**: accessible, secure and easy to integrate across an organisation.
